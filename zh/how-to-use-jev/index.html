如何使用 Jev

让编程助手帮你搭建 Jev 判断流程。先选一个目标明确的小任务，用你能逐条核对的样本跑通，再接入实际业务。

本页目录1. 开通 TypeSafe 账号2. 安装 TypeSafe 技能3. 配置 API 密钥4. 把任务要求交给编程助手接入真实业务前，检查这些结果

1. 开通 TypeSafe 账号

访问 TypeSafe 官网，按照当前流程申请或开通访问权限，再登录 控制台。是否需要申请、何时获批，以 TypeSafe 当时的安排为准。

先明确要解决哪个判断问题。例如：把收到的咨询分配给对应部门。列出允许返回的选项，并约定无法归类时如何处理。

2. 安装 TypeSafe 技能

技能为编程助手提供接入 TypeSafe 的指导。按你使用的工具选择一种安装方式即可。

Codex 等支持的编程助手

npx skills add typesafe-ai/skills --skill typesafe-ai

出现提示时，选择你使用的编程助手。

Claude Code

claude plugin marketplace add typesafe-ai/skills
claude plugin install typesafe@typesafe-ai

以上命令来自 TypeSafe 官方技能仓库。安装技能后，仍需配置自己的 API 账号和密钥。

3. 配置 API 密钥

在 TypeSafe 控制台创建 API 密钥，将它配置为运行程序环境中的 TYPESAFE_API_KEY；部署到服务器时，使用托管平台的服务端密钥配置。

不要把密钥写进公开仓库或浏览器 JavaScript。将来如果需要网页界面，应通过自己的后端调用 API。本教程不要求你在 JEV Demo 上填写密钥。

4. 把任务要求交给编程助手

说清楚输入是什么、允许哪些判断结果，以及不确定时怎么办。下面这段提示词可以按你的场景修改：

使用 TypeSafe skill，帮我写一个脚本，读取我的客服工单样本，将每条分到：账单、技术支持、销售或其他。输出分类及置信度，使用可配置的阈值将不确定的结果标记为人工复核。通过 TYPESAFE_API_KEY 读取密钥。只用样本数据测试，把输出与我提供的预期分类并排展示。不要自动回复，也不要修改真实工单。

这是一份任务示例，不代表已经完成实测。先检查生成的代码和样本结果，再决定是否接入真实数据。

接入真实业务前，检查这些结果

  • 样本应包含模糊表达和应归为“其他”的情况，不只测试容易判断的内容。
  • 将输出与预期分类比较，逐条查看错误及其原因。
  • 根据误判代价设定人工复核阈值；置信度高不等于一定正确。
  • 限制重试次数，并约定 API 暂时不可用时的处理方式。
  • 用真实用量记录评估成本，再逐步扩大处理规模。

可以先用 tokens calculator 估算费用。其中的节省比例由你填写，不代表实测效果。
